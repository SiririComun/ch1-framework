\subsection{Plataforma de Adquisición: \texttt{hw-xadc-dma-overlays}}
\label{subsec:hw_overlay}

Para validar el marco de trabajo propuesto y establecer una plataforma preliminar de pruebas para sistemas de adquisición de datos (DAQ), se desarrolló el repositorio de firmware \texttt{hw-xadc-dma-overlays}, orientado a la tarjeta SoC-FPGA PYNQ-Z2 (dispositivo Zynq-7000 \texttt{xc7z020clg400-1}). Este proyecto implementa una plataforma de adquisición en la Lógica Programable (PL) capaz de digitalizar señales analógicas a alta velocidad y transferirlas hacia la memoria DDR del procesador (PS) sin intervención de la CPU.

\subsubsection{Arquitectura de Adquisición y Flujo AXI4-Stream}
La arquitectura de adquisición se diseñó utilizando Vivado 2024.2.2 bajo la metodología de IP Integrator (Figura~\ref{fig:xadc_bd_diagram}). El flujo de señal se articula mediante los siguientes bloques principales:

\begin{enumerate}
    \item \textbf{Digitalizador XADC (\texttt{xadc\_wiz\_0}):} Configurado en modo canal único sobre la entrada auxiliar diferencial \texttt{VAUXP1/VAUXN1}, operando a una frecuencia de muestreo de $1~\text{MSPS}$ (1000~kSPS). La interfaz de salida fue establecida en formato AXI4-Stream de 16 bits (\texttt{M\_AXIS}).
    \item \textbf{Generador de TLAST (\texttt{tlast\_generator}):} Módulo VHDL personalizado que actúa como empaquetador de flujo, asertando la señal \texttt{TLAST} combinacionalmente cada $N = 16\,384$ muestras (\texttt{PACKET\_SIZE}) para delimitar las ráfagas de memoria requeridas por el motor DMA.
    \item \textbf{Acceso Directo a Memoria (\texttt{axi\_dma\_0}):} Motor DMA operando en modo \textit{Simple DMA} directo (S2MM) con un tamaño de ráfaga de 128 transferencias. Los datos son transmitidos a través del interconector de datos (\texttt{axi\_mem\_intercon}), adaptando el flujo de 32 bits del DMA hacia el bus de alto rendimiento AXI-HP0 de 64 bits del Zynq PS. Esta transferencia directa a memoria DDR (\texttt{0x00000000} -- \texttt{0x1FFFFFFF}) alcanza un \textit{throughput} sostenido de hardware de $1.75~\text{MB/s}$, liberando por completo a la CPU de tareas de procesamiento de muestra por muestra.
    \item \textbf{Temporizador AXI y Medición de Latencia (\texttt{axi\_timer\_0}):} Bloque de apoyo cuya entrada de captura (\texttt{capturetrig0}) se conecta a la señal \texttt{TLAST}, permitiendo registrar con precisión de $10~\text{ns}$ ($100~\text{MHz}$) la finalización de paquetes desde la PL.
    \item \textbf{Infraestructura de Interconexión y Reloj:} El bloque \texttt{processing\_system7\_0} genera un reloj de sistema de $100~\text{MHz}$ (\texttt{FCLK\_CLK0}) y un reseteo sincronizado mediante \texttt{rst\_ps7\_0\_100M}. La distribución de comandos de control desde el PS se gestiona mediante el conmutador AXI SmartConnect (\texttt{axi\_smc}) sobre el bus \texttt{M\_AXI\_GP0}, mapeando las direcciones de registro del DMA (\texttt{0x40400000}), del temporizador (\texttt{0x42800000}) y del XADC (\texttt{0x43C00000}).
\end{enumerate}

\subsubsection{Gestión de Firmware con CERN Hog y Despliegue CI/CD}
La construcción y control de versiones del proyecto se gestionaron mediante CERN Hog (\texttt{Top/pynq\_z2/}), utilizando archivos de listas (\texttt{.src}) para desacoplar el código VHDL y el diagrama de bloques (\texttt{xadc.bd}) de los archivos binarios propietarios de Vivado.

El \textit{wrapper} de nivel superior (\texttt{xadc\_wrapper.vhd}) incorpora genéricos de versión (\texttt{GLOBAL\_VER}, \texttt{GLOBAL\_SHA}), embebiendo dinámicamente el \textit{hash} de Git en los registros de hardware durante la síntesis. Un script TCL de gancho (\texttt{post-bitstream.tcl}) extrae automáticamente los archivos binarios compilados (\texttt{pynq\_z2.bit} y \texttt{pynq\_z2.hwh}) a la carpeta \texttt{bin/}. Finalmente, un flujo de integración continua en GitHub Actions (\texttt{release.yml}) empaqueta y publica automáticamente estos artefactos binarios en los lanzamientos del repositorio al detectar etiquetas de versión (\texttt{v*}).

\subsection{Interfaz e Instrumentación: \texttt{sw-pynq-oscilloscope}}
\label{subsec:sw_oscilloscope}

Para abstraer la complejidad del hardware en la Lógica Programable (PL) y ofrecer una interfaz interactiva de alto nivel, se desarrolló la librería en Python \texttt{pynq-oscilloscope} (\texttt{sw-pynq-oscilloscope}), disponible en PyPI (\texttt{pip install pynq-oscilloscope}). Esta capa de software permite controlar el hardware de adquisición, automatizar estímulos analógicos mediante hardware en el lazo (HIL) y visualizar señales en tiempo real en entornos Jupyter Notebook.

\subsubsection{Carga Autónoma de Hardware y Controladores DMA}
\begin{itemize}
    \item \textbf{Carga Autónoma (\texttt{HardwareLoader}):} Inspecciona \texttt{hardware.json} (\texttt{v1.0.2}), detecta el modelo de la tarjeta objetivo (\texttt{\$BOARD}), consulta la API de GitHub Releases, descarga los archivos binarios \texttt{pynq\_z2.bit} y \texttt{pynq\_z2.hwh} a un directorio de caché local (\texttt{\textasciitilde/.cache/pynq\_oscilloscope/v1.0.2/}) y carga la firma en la FPGA.
    \item \textbf{Controlador DMA (\texttt{StreamingXADC}):} Realiza una preasignación de memoria contigua (CMA) fuera del bucle de captura mediante \texttt{pynq.allocate(shape=(16384,), dtype='u2')}. Al invocar \texttt{capture()}, desencadena la transferencia DMA S2MM, espera la aserción de \texttt{TLAST} en la muestra 16\,384, realiza el alineamiento de bits (\texttt{raw \textgreater\textgreater\ 4}) y escala la señal al rango físico ($0.0~\text{V}$ a $3.3~\text{V}$).
\end{itemize}

\subsubsection{Estímulo HIL y Cuadro de Mando Interactivo}
Para validar la respuesta dinámica del framework sin instrumental externo costoso, se integró el instrumento Digilent Analog Discovery 3 (AD3) mediante la librería \texttt{pydwf}:
\begin{itemize}
    \item \textbf{Gestión de Entorno (\texttt{EnvironmentManager}):} Instala automáticamente los paquetes Debian de Digilent Adept y WaveForms SDK para arquitecturas ARM (32/64 bits) y gestiona los permisos de bus USB (\texttt{/dev/bus/usb/}).
    \item \textbf{Estímulo HIL No Bloqueante (\texttt{AD3SignalGenerator}):} Ejecuta la generación de señales (seno, cuadro, triángulo) en un hilo secundario (\textit{daemon thread}), permitiendo modificar parámetros en tiempo real sin congelar el kernel de Jupyter.
    \item \textbf{Panel Interactivo (\texttt{OscilloscopeDashboard}):} Construido con \texttt{ipywidgets} y Plotly \texttt{FigureWidget} (Figura~\ref{fig:oscilloscope_dashboard}). Implementa enlaces de cliente de cero latencia (\texttt{widgets.jslink()}), disparo por software por flanco de subida (\texttt{np.where}) y renderizado atómico (\texttt{fig.batch\_update()}).
\end{itemize}

\subsubsection{Validación del Framework mediante Caracterización HIL}
La suite de caracterización en lazo cerrado (\texttt{04\_automated\_performance\_benchmark.ipynb}) sirvió para verificar experimentalmente que el flujo de co-diseño propuesto preserva la fidelidad de la señal y alcanza un alto rendimiento de software:
\begin{itemize}
    \item \textbf{Respuesta y Calidad de Señal:} Se midió un ancho de banda analógico a $-3~\text{dB}$ de $150.0~\text{kHz}$, una relación señal-ruido de $\text{SNR} = 45.96~\text{dB}$ ($\text{ENOB} = 7.34~\text{bits}$ para entrada senoidal de $50~\text{kHz}$) y un error medio de offset DC menor a $9.69~\text{mV}$ (precisión estática $>99.7\%$).
    \item \textbf{Rendimiento de Interfaz:} El panel interactivo alcanzó una tasa de refresco fluida de $53.3~\text{cuadros/s (FPS)}$ con un \textit{throughput} sostenido de $1.75~\text{MB/s}$, demostrando que la capa PYNQ procesa eficazmente el flujo masivo de datos proveniente de la PL.
\end{itemize}

\subsection{Proyección a Módulos de Localización Espacial}
\label{subsec:proyeccion_localizador}

La implementación y caracterización experimental de los repositorios \texttt{hw-xadc-dma-overlays} (Sección~\ref{subsec:hw_overlay}) y \texttt{sw-pynq-oscilloscope} (Sección~\ref{subsec:sw_oscilloscope}) constituyen la prueba de concepto que valida la solidez del marco de trabajo (\textit{framework}) co-diseñado. Los resultados confirman que la combinación de los entornos CERN Hog y AMD PYNQ permite construir instrumentación científica abierta de alto rendimiento, logrando transferencias deterministas por DMA a $1.75~\text{MB/s}$ y tasas de refresco interactivas de $53.3~\text{cuadros/s}$ sin generar cuellos de botella en la CPU ni en la interfaz gráfica.

Un aspecto fundamental demostrado en este capítulo es el desacoplamiento arquitectónico entre la capa de hardware en la Lógica Programable (PL) y la capa de abstracción en software (PS):
\begin{itemize}
    \item \textbf{Infraestructura Consolidada e Invariante:} El flujo de transporte de datos impulsado por eventos (AXI4-Stream), el empaquetado de muestras (\texttt{tlast\_generator}), el motor AXI DMA sobre el bus de 64 bits AXI-HP0, la asignación de memoria contigua en Python (\texttt{StreamingXADC}) y la carga autónoma de artefactos (\texttt{HardwareLoader}) se mantendrán como la columna vertebral invariable del sistema.
    \item \textbf{Escalabilidad hacia la Localización de Fuentes de Ondas:} En los capítulos siguientes, el módulo de prueba de canal único de la XADC se sustituirá por arreglos geométricos de sensores multicanal e integraciones con núcleos IP de procesamiento digital de señales (DSP) en la PL (Capítulo~2 y Capítulo~3). Debido a que la tubería (\textit{pipeline}) AXI DMA y la capa PYNQ son agnósticas al tipo de dato transmitido, la adición de algoritmos de estimación de ángulo de llegada (AoA) o diferencia de tiempo de llegada (TDOA) en hardware no requerirá reestructurar la capa de distribución en software ni la interfaz de usuario.
\end{itemize}

De este modo, el marco de trabajo no solo resuelve el problema de la falta de reproducibilidad y versionado en firmware FPGA, sino que garantiza que la plataforma completa para la localización espacial de fuentes de ondas se construya sobre una base metodológica probada, modular y completamente abierta.

\section{Conclusiones del Capítulo}
\label{sec:conclusiones_ch1}

\begin{enumerate}
    \item Se estableció una metodología de co-diseño hardware/software para instrumentación científica abierta basada en los entornos CERN Hog y AMD PYNQ, resolviendo la falta de trazabilidad y el desacoplamiento tradicional entre el desarrollo de firmware FPGA y las aplicaciones de usuario.
    \item La integración de CERN Hog en el repositorio de hardware (\texttt{hw-xadc-dma-overlays}) permitió automatizar la construcción de proyectos en Vivado mediante scripts TCL y pipelines de CI/CD en GitHub Actions, garantizando que cada artefacto ejecutable (\texttt{.bit} y \texttt{.hwh}) esté vinculado de forma inequívoca al \textit{hash} de un commit de Git.
    \item La capa de software (\texttt{sw-pynq-oscilloscope}), distribuida mediante PyPI, demostró la viabilidad de empaquetar plataformas SoC-FPGA como librerías estándar en Python. El módulo \texttt{HardwareLoader} elimina la necesidad de configuración manual de archivos de firmware al descargar autónomamente los mapas de bits requeridos desde los lanzamientos del repositorio de hardware.
    \item El empaquetador VHDL diseñado (\texttt{tlast\_generator}) resolvió la limitación nativa de delimitación de paquetes del núcleo XADC, permitiendo transferencias continuas por AXI DMA hacia la memoria RAM compartida a $1.75~\text{MB/s}$ con una latencia de hardware medible a $100~\text{MHz}$ mediante el temporizador AXI.
    \item La suite de caracterización en lazo cerrado validó la fidelidad del flujo de adquisición, alcanzando un ancho de banda analógico de $150.0~\text{kHz}$, una relación señal-ruido de $45.96~\text{dB}$ ($\text{ENOB} = 7.34~\text{bits}$), una precisión estática superior al $99.7\%$ y un despliegue gráfico fluido a $53.3~\text{FPS}$. Esta infraestructura validada servirá como la base operativa para la implementación del localizador espacial de fuentes de ondas en los capítulos posteriores.
\end{enumerate}
